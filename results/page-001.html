Assistant2026-04-07T12:02:00.465Z

Fast cold starts under 50ms is a tough target. Here's the realistic landscape:

Fastest Options

1. Cloudflare Workers (V8 Isolates)

  • Cold starts: ~0-5ms — the gold standard
  • Uses V8 isolates instead of containers, so no OS-level boot
  • JavaScript/TypeScript, WASM, or languages that compile to WASM
  • No Node.js globals by default (Workers runtime, not Node)

2. Fastly Compute (formerly Compute@Edge)

  • Cold starts: ~50ms or under — borderline for your target
  • WASM-based, runs Rust/Go/JS compiled to WASM
  • Strong isolation guarantees

3. Deno Deploy

  • Cold starts: ~50ms range
  • V8-isolate model similar to Workers
  • TypeScript-native

What Makes These Fast

The key difference is isolate-based vs container-based runtimes:

Model Examples Cold Start
V8 isolates CF Workers, Deno Deploy <10ms
MicroVMs (Firecracker) Lambda SnapStart, Fly Machines 100-300ms
Containers Lambda (default), Cloud Run 500ms-3s

Practical Recommendation

Cloudflare Workers is the clear winner if your code can run in their runtime. The constraints: - No arbitrary filesystem access - No long-running processes - CPU time limits per request (10-50ms depending on plan) - Limited to JS/TS/WASM

If you need arbitrary language support with near-50ms cold starts, the target is extremely hard to hit. Cloudflare Workers is essentially the only production option that reliably lands under 10ms.

What language/runtime does your workload need? That narrows it significantly.

## Key Performance Improvements

In cold start tests using common packages, Cloudflare Workers start over 2.4x faster than AWS Lambda without SnapStart and 3x faster than Google Cloud Run.

## Memory Snapshot Technology

Every time you deploy a Python Worker, a memory snapshot is captured after the top level of the Worker is executed. This snapshot captures all imports, including package imports that are often costly to load. The memory snapshot is loaded when the Worker is first started, avoiding the need to reload the Python runtime and all dependencies on each cold start.

## Real-World Performance Impact

Python Workers now feature improved cold start performance, reducing initialization time for new Worker instances. This improvement is particularly noticeable for Workers with larger dependency sets or complex initialization logic.

Without any memory snapshot, the cold start for a benchmark with common packages takes around 10 seconds, so this change improves cold start times significantly.

## Technical Approach

Cloudflare scans the Worker's code for import statements, execute them, and then take a snapshot of the Worker's WebAssembly linear memory. Effectively, they perform the expensive work of importing packages at deploy time, rather than at runtime.

The results show Cloudflare is positioning Python Workers as a viable option for performance-critical serverless applications with fast cold start times compared to competitors.
