await vm.exec("echo 'hello world'");

const res = await vm.python.runCode({

**Response Structure:** All code execution methods return:
- `result`: Parsed JSON output (if valid JSON in stdout)
- `stdout`: Raw standard output
- `stderr`: Standard error output
- `statusCode`: Process exit code

## 3. How to Snapshot/Checkpoint a VM

### Method 1: Snapshot Existing VM
```javascript
const { vm } = await freestyle.vms.create();
await vm.exec("apt-get update && apt-get install -y nginx");
const snapshotId = await vm.snapshot();
```

**Live Snapshots:** Running or suspended machines generate "live" snapshots that resume instantly (full memory state saved).

### Method 2: Declarative Snapshots via VmSpec
```javascript
import { VmSpec } from "freestyle-sandboxes";

const spec = new VmSpec()
  .repo("owner/my-app", "/app")
  .systemdService({
    name: "install-deps",
    exec: ["npm install"],
    workdir: "/app"
  });

const { vm } = await freestyle.vms.create({ snapshot: spec });
```

### Creating VM from Snapshot
```javascript
const { vm } = await freestyle.vms.create({ snapshotId });
```

### Layering on Snapshots
```javascript
const { vm } = await freestyle.vms.create({
  snapshot: spec,
  additionalFiles: { "/tmp/file.txt": { content: "data" } }
});
```

**Performance:** First creation with unique configuration may take longer, but subsequent VMs with identical specs return cached snapshots instantly.

| Method | Purpose |

### Configuration Options

Common parameters in `freestyle.vms.create()`:
- `with`: Object containing language integrations (e.g., `{ python: new VmPython() }`)
- `additionalFiles`: Map of files to add to VM filesystem
- `gitRepos`: Array of git repositories to clone
- `workdir`: Working directory for operations
- `domains`: Custom domain mappings
- `idleTimeoutSeconds`: Auto-suspend timeout
- `rootfsSizeGb`: Root filesystem size
- `waitForReadySignal`: Wait for startup completion
